## Verdict in one line

## 2. The three defects (code review of the live path)

### A. Un-paced yfinance burst — the outage amplifier (regression, now fixed)
`scanner.py` called `_yf_daily()` directly, with no throttle. Pre-PR#3 this was harmless
because Dhan’s retry back-off paced the pipeline; post-PR#3 (fail-fast) an entire universe
of ~800 symbols hits Yahoo within a minute → IP-level 429 → `_yf_daily` returns `None` for
everything → `errors ≈ 800`, `signals = 0`.
**Fix:** every fallback call now goes through `_YfGate` — a process-wide pacer
(`yf_min_interval = 0.6 s` across all workers) with one quick retry on a transient failure,
and an instant short-circuit if yfinance isn’t importable at all.

### B. A data outage looked exactly like a quiet day (the reason you noticed nothing)
The old code counted the errors, then cheerfully printed/sent **“No pattern signals today”**
with a green run. **Fix now:**
- run_live flags an outage when **≥ 50 % of ≥ 25 symbols** fetch nothing
  (`data_outage_error_frac`, `data_outage_min_symbols`);
- the Actions log gets a `::error::` annotation, the summary a `🛑 data: OUTAGE …` line;
- Telegram gets a distinct **“🛑 SCAN DEGRADED — data outage”** message instead of the
  polite quiet-day text;
- `scanner.py` exits **3** (`EXIT_DATA_OUTAGE`) → the scheduled workflow run turns **red ❌**,
  so you see breakage without opening the logs.

### C. Fallback data was silently one day stale
`yfinance.history(end=…)` is **exclusive**; `_yf_daily` passed `to_date` directly, so any
fallback-carried run (i.e. every Dhan-dead day) scanned the market *as of yesterday* —
systematically late for a pattern that punishes lateness (`bos_newest…bos_oldest`,
`flush_max_age = 3`). **Fix:** `end = to_date + 1 day`.

### D. Minor hardening shipped with this fix
- 4xx from Dhan that is not auth (401/403) and not throttling (429) no longer gets three
  zero-sleep retries — new `DhanClientError`, single attempt (zero-sleep hammering provokes
  stricter throttling).
- Quiet days now say **why**: the summary includes a `prefilter rejects:` tally
  (e.g. `weekly RSI 512 · daily candle red 97 · close < min 201`) and a
  `data health: N/M fetched` line.
- Error strings now name both sources: `dhan[…]+yf[failed]`.

## 3. Why alerts are rare even when the scanner is healthy (by design)

This hasn’t changed and is worth repeating, because Aug 19–24 were fair-weather quiet days:

```
~2100-symbol universe → mcap ≥ 1000 Cr → top-800 cap
  → panel prefilter: close > ₹100 AND green daily AND weekly RSI(14) > 60 AND weekly MACD hist > 0
  → pattern: BOS (2–12 bars) → ≥6 % flush to the SSL shelf (wick −1%/+1.5 %) → all closes hold
    → green reversal ≥ +1.8 %, body ≥ 0.25, still below peak
  → score ≥ 70
```

- The panel prefilter is structurally hostile to this counter-trend pattern: the deep flush
  that earns the most score points also crushes weekly RSI/MACD (your own Aug-18 signal
  cleared the RSI gate by 1.6 points).
- Backtest frequency: ~0.26 score≥55 signals/stock/year; at **score ≥ 70**, expect roughly
  **1–3 alerts per month across the whole market**, with multi-week zero stretches being
  normal. Since Aug 18: **zero** qualifying setups (correctly) → Aug 24 → then blind.
- The intraday workflow scans only `watchlist.txt` (~130 symbols).
- Note: the cross-run cooldown can’t function in CI yet — `signals_tracker.csv` is still not
  persisted across Actions runs (needs the `actions/cache` step; see §5).
